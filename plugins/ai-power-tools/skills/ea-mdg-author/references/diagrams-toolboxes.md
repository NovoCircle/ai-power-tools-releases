Back to [SKILL.md](../SKILL.md).

## Section 2 — Custom Diagram Type

```xml
<Stereotype name="WBAApplicationView"
            alias="WBA Application Architecture"
            notes="Application portfolio architecture diagram."
            cx="90" cy="70"
            bgcolor="-1" fontcolor="-1" bordercolor="-1" borderWidth="-1">
  <AppliesTo>
    <Apply type="Diagram_Logical">
      <Property name="alias"     value="WBA Application Architecture"/>
      <Property name="diagramID" value="WBA-AppView"/>
      <Property name="toolbox"   value="WBA::WBA ArchiMate"/>
    </Apply>
  </AppliesTo>
</Stereotype>
```

This is the `WBAApplicationView` diagram stereotype, with `toolbox` set to
`<technology id>::<name of the toolbox's UML profile>`, as in the shipped Westbrook demo MDG
(1.1.1): `WBA ArchiMate` is the UML profile that holds the page `WBA ArchiMate Elements`
(Section 3). Its diagrams resolve and switch the toolbox (measured on EA 17.1, 2026-10-07; its 1.0
and 1.1.0 builds, with the same string, never resolved their diagrams, and 1.1.1 differs by naming
the diagram profile `WBA`). The page name does not work here (next section).

**Rules:**
- `Apply type="Diagram_Logical"` — the correct value for EA 17 custom diagrams (NOT `"Logical"`)
- `Property name="toolbox"` names the toolbox's **UML profile**, not its page: `<YourTechID>::<toolbox UML profile name>`, or the profile name alone. Naming the page (`<YourTechID>::PageName` or `PageName`, the `<Stereotype name="...">` in UIToolboxes) is measured to fail: the diagram opens and the Toolbox keeps showing the previous diagram's page
- `Property name="alias"` — the display name shown in the New Diagram dialog
- EA 17.0 shows the stereotype `name` (e.g., "WBAApplicationView") in the Model Builder/New Diagram dialog, NOT the `alias` attribute

### Checking a toolbox form on a scratch model

What is measured (EA 17.1 build 1716: the Westbrook demo MDG 1.1.1, generated by EA from its
source model, on 2026-10-07; nine test technologies, one form changed in each, written directly
into a scratch model file as Location: Model technology rows (not imported through EA's dialogs),
which EA loaded and enabled, on 2026-11-16. Each form was tried once):

| Form | Result |
|---|---|
| `toolbox` = `<technology id>::<toolbox UML profile name>` (`WBA::WBA ArchiMate`) | Works: the page appears and switches with the diagram type |
| `toolbox` = `<toolbox UML profile name>` (no technology id) | Works: the page appears |
| `toolbox` = `<technology id>::<toolbox page name>` (`WBA::WBA ArchiMate Elements`) | Fails: the Toolbox keeps the previous diagram's page |
| `toolbox` = `<toolbox page name>` | Fails, the same way |
| Toolbox item tag = `<UML profile name of the stereotype>::<stereotype>(UML::<metaclass>)` (the generated form) | Works: the item creates the element with the stereotype bound |
| Toolbox item tag = `<UML profile name of the stereotype>::<stereotype>` (no metaclass suffix) | Works, for a stereotype that applies to one metaclass |
| Toolbox item tag = `<technology id>::<stereotype>`, where the technology id is not the profile's name | Fails: EA says "No profile found with id '<technology id>'" and creates nothing |
| Toolbox item tag = `<UML profile Documentation id>::<stereotype>` | Fails, the same message |
| UML profile id equal to the technology id, or an id derived from a GUID | Both work |

To measure another form: make a scratch model, give it one technology file per variant (change only the
form under test), import each at Location: Model, restart EA, open a diagram of each type, and
look at the Toolbox (screenshot it; do not rely on System Output). A form works when the page
appears on opening the diagram and changes when the diagram type changes. Record the form, the
EA build and the result.

## Section 3 — Toolbox Pages

```xml
<!-- Each toolbox page is one Stereotype with Apply type="ToolboxPage" -->
<!-- A shortened "WBA ArchiMate Elements" page — one of the WBA technology's three. The shipped
     1.1.1 page lists 12 items, in the form <profile name>::WBABusinessApplication(UML::Component) -->
<Stereotype name="WBA ArchiMate Elements" notes="">
  <AppliesTo>
    <Apply type="ToolboxPage"/>
  </AppliesTo>
  <TaggedValues>
    <!-- Each Tag is one item in the toolbox palette -->
    <!-- Tag name format: <UML profile name of the stereotype>::StereotypeName(UML::<metaclass>).
         Here the stereotypes come from the UML profile named WBADomainProfile (the skeleton in
         xml-skeleton.md); use your profile's name. -->
    <!-- Tag default: the display label shown in the palette -->
    <Tag name="WBADomainProfile::WBABusinessApplication(UML::Component)" type="" description="" unit="" values="" default="Business Application"/>
    <Tag name="WBADomainProfile::WBABusinessService(UML::Component)"     type="" description="" unit="" values="" default="Business Service"/>
    <Tag name="WBADomainProfile::WBAVendorSystem(UML::Component)"        type="" description="" unit="" values="" default="Vendor System"/>
  </TaggedValues>
</Stereotype>

<!-- PROPOSED EXTENSION — not part of the shipped WBA technology (see Section 1 -
     Connector Stereotype above: WBA ships `Uses`, `Flows` and `realizes`, not this one). Shown only
     to teach how a connector toolbox page is wired up. -->
<Stereotype name="WBA Connectors (proposed)" notes="">
  <AppliesTo>
    <Apply type="ToolboxPage"/>
  </AppliesTo>
  <TaggedValues>
    <Tag name="WBADomainProfile::WBARunsOn(UML::Dependency)" type="" description="" unit="" values="" default="Runs On"/>
  </TaggedValues>
</Stereotype>
```

**Rules:**
- The `Stereotype name=` (e.g., `"WBA ArchiMate Elements"`) is the toolbox page name. The diagram's `toolbox` property must not name it: it names the UML profile that holds the page (`WBA::WBA ArchiMate`; see Section 2)
- The `Tag name=` prefix is the **name** of the UML profile that defines the stereotype (in the generated WBA 1.1.1 that profile carries the technology's display name), not the technology id and not the profile's Documentation `id`. Either of those gives EA's "No profile found" message when the item is used (a profile named the same as the technology id was not measured). The generated file adds `(UML::<metaclass>)`; it was not needed for a stereotype that applies to one metaclass
- Multiple pages allowed — one `Stereotype` per page, all inside the same UIToolboxes `<Content>`. The real WBA technology ships three: `WBA ArchiMate Elements`, `WBA BPMN Elements`, `WBA UML Elements`.

## COLORREF Color Reference

Formula: `B × 65536 + G × 256 + R`

| Color | R | G | B | COLORREF |
|--------|---|---|---|----------|
| Light blue | 180 | 210 | 240 | **15782580** |
| Light grey | 221 | 221 | 221 | **14540253** |
| Light green | 204 | 255 | 204 | **13434828** |
| Light amber | 255 | 220 | 100 | **6610175** |

Verify any value: `R = val & 0xFF`, `G = (val >> 8) & 0xFF`, `B = (val >> 16) & 0xFF`

> **Common mistake:** the formula is BGR order (not RGB). `12632319 = 0x00C0C0FF = RGB(255,192,192)` = pink, not blue.

## ID Mapping Pattern

When IDs exceed 12 characters, map them systematically:

| Logical Name | MDG `id=` |
|---|---|
| Technology root | `WBA` |
| UML Profile | `WBA` (the technology id, or any other id: both work; item tags use the profile's `name`) |
| Diagram Profile | `WBA-Diag` |
| Toolbox | `WBA-TB` |
